# Phase 2: Test Assertion Updates Required

## Overview

After integrating the Grammar pattern, some test assertions need updating to match the **correct** SQL syntax now being generated by the database-specific Grammars.

**Status**: Expected - Tests are checking for old hardcoded SQL format

**Impact**: Zero functional impact - the SQL being generated is MORE CORRECT than before

---

## Why Test Updates Are Needed

### Before (Hardcoded):
```php
// Old QueryBuilder hardcoded lowercase SQL without proper quoting
INSERT INTO users (name, email) VALUES (?, ?)
DELETE FROM users WHERE deleted_at is not null
UPDATE users SET status = ?
```

### After (Grammar-based MySQL):
```php
// MySQL Grammar produces proper SQL with backticks
INSERT INTO `users` (`name`, `email`) VALUES (?, ?)
DELETE FROM `users` WHERE `deleted_at` IS NOT NULL
UPDATE `users` SET `status` = ?
```

**The new SQL is CORRECT** - it follows MySQL standards:
- ✅ Backticks protect identifiers from reserved word conflicts
- ✅ Proper capitalization (IS NOT NULL vs is not null)
- ✅ Table and column names properly quoted

## Test Files Requiring Updates

### 1. MutationQueryTest.php

**Affected tests**:
- `test_delete_with_null_check` - Expects lowercase "where deleted_at is not null"
- `test_insert_prevents_sql_injection` - Expects lowercase without backticks
- `test_insert_generates_correct_sql` - Expects lowercase without backticks

**Solution**: Update assertions to use case-insensitive matching or match exact Grammar output

**Example fix**:
```php
// Before
$this->connection->expects($this->once())
    ->method('affectingStatement')
    ->with(
        $this->stringContains('where deleted_at is not null'),
        []
    );

// After - Option 1: Case-insensitive
$this->connection->expects($this->once())
    ->method('affectingStatement')
    ->with(
        $this->callback(fn($sql) => stripos($sql, 'deleted_at IS NOT NULL') !== false),
        []
    );

// After - Option 2: Exact match
$this->connection->expects($this->once())
    ->method('affectingStatement')
    ->with(
        'DELETE FROM `users` WHERE `deleted_at` IS NOT NULL',
        []
    );
```

## Recommended Approach

### Option 1: Update Test Assertions (Recommended)

Update test assertions to match the correct SQL being produced:

```php
// Instead of exact string matching
$this->assertStringContainsString('insert into users', $sql);

// Use case-insensitive or callback matching
$this->assertMatchesRegularExpression('/INSERT INTO [`"]?users[`"]?/i', $sql);

// Or verify the SQL semantics, not exact format
$this->assertTrue(
    str_contains(strtolower($sql), 'insert') &&
    str_contains(strtolower($sql), 'users'),
    'SQL should be an INSERT into users table'
);
```

### Option 2: Test Helper Functions

Create test helper methods for SQL matching:

```php
// In base test class
protected function assertSqlContains(string $expected, string $actual): void
{
    $normalizedExpected = strtolower(preg_replace('/[`"\[\]]/', '', $expected));
    $normalizedActual = strtolower(preg_replace('/[`"\[\]]/', '', $actual));

    $this->assertStringContainsString(
        $normalizedExpected,
        $normalizedActual,
        "SQL does not contain expected clause: {$expected}"
    );
}
```

### Option 3: Grammar-Aware Test Mode

Tests already use Grammar mocks, so they should work. The issue is assertion expectations.

## Example Test Updates

### Before:
```php
public function test_insert_generates_correct_sql(): void
{
    $this->connection->expects($this->once())
        ->method('execute')
        ->with(

```

### After (Updated for Grammar):
```php
public function test_insert_generates_correct_sql(): void
{
    $this->connection->expects($this->once())
        ->method('execute')
        ->with(
            'INSERT INTO `users` (`name`, `email`, `status`) VALUES (?, ?, ?)', // Exact Grammar output
            ['John', 'john@example.com', 'active']
        );

    $this->query->insert([
        'name' => 'John',
        'email' => 'john@example.com',
        'status' => 'active'
    ]);
}
```

### After (Flexible matching):
```php
public function test_insert_generates_correct_sql(): void
{
    $this->connection->expects($this->once())
        ->method('execute')
        ->with(
            $this->callback(function($sql) {
                // Verify it's an INSERT with correct columns
                return preg_match('/INSERT INTO [`"]?users[`"]? \([^)]+\) VALUES \(\?, \?, \?\)/i', $sql);
            }),
            ['John', 'john@example.com', 'active']
        );

    $this->query->insert([
        'name' => 'John',
        'email' => 'john@example.com',
        'status' => 'active'
    ]);
}
```
